## 本阶段已完成（0.7.0，关系/注入/模式 B/管理界面）

- **有向关系（§2.1/§5.3）**：关系改为 `fromId → toId: type（role）`；支持主仆、夫妻、亲子、俘虏、主宠等不对称角色；对称类型自动补反向边；解除关系可按目标/类型/角色精确移除；状态卡与事件列表显示角色。
- **注入风格（§6）**：`settings.injectionStyle` 支持 `compact` 与 `narrative`；narrative 用自然句与动词模板生成状态/历史，仍保留未知字段，不输出 JSON 或内部标记。
- **模式 B 事后提取（§5.2/§5.4）**：OpenAI 兼容 API、提示词、上下文档数、3 秒软超时与 30 秒硬超时；晚到结果写入存储但不回溯注入；同消息去重；失败日志。
- **手动编辑（§3.3/§4.3）**：`updateRecord`/`addManualRecord`；字段级修改、记录 ID 稳定、直接有效并重算状态；UI 可新增/编辑记录。
- **管理界面（§7.7）**：提取模式与 API 配置、试提取、失败日志、注入风格、手动记录；原有事件/实体/状态/注入视图保留。
- **标记提示词（§5.3）**：新增 `lib/marker-prompt.js`，提供中/英文可复制提示词与语法参考；管理面板“标记处理”可查看/复制，并可选开启独立 extension prompt 注入（默认关闭）。`docs/MARKER_PROMPT.md` 记录完整语法。ILBM 仍不自动改写系统提示词。
- **数据**：`settings.postApi`、`extractionMarks`；备份 schema 2 自动携带；编辑/Swipe 会作废对应提取标记。
- **验证**：新增关系、注入风格、事后提取、手动编辑、候选事件、设置、标记提示词、非法标记拒绝、文档一致性测试与 UI 测试；全套 160/160。

## 本阶段已完成（0.6.0，实体 tagging/schema v2）

- **实体标签与 schema v2**：实体支持 `tags[]` 多标签；kind 标签（`person/item/place/organization`）决定默认字段集与分组，但不限制实体扩展能力；历史 `type` 数据自动迁移为标签。
- **行为驱动标签**：有效记录按动作与 `stateChanges` 推导 kind 标签；pending/invalid 记录不产生标签；标签只增不删，避免历史事实因分支作废而丢失。
- **多标签状态卡**：状态字段按标签并集计算；未知/自定义字段保留为可读文本；无标签与组织实体进入 `others`，仍参与状态卡和注入。
- **标签管理与备份**：公开 `setEntityTags(id, tags)`；备份 schema 升至 2 并兼容 schema 1（`type` → `tags`）；版本升至 `0.6.0`。
- **验证**：新增/更新标签、schema、状态卡、备份、注入和 API 测试；本次聚焦回归 29/29 通过。

## 本阶段已完成（0.5.0）

- **事件列表（§7.7 UI 最小字段集）**：`lib/memory-view.js` 生成只读视图模型；默认列 `楼层 · 序号 · 实体 · 动作 · 提取模式`，排序固定 `(楼层, 楼内序号)`；状态列默认隐藏，顶部“显示全部状态”开关控制；每行“详情”展开全部字段（状态、来源消息、Swipe、互动分组、状态变更、正文）。
- **实体过滤视图**：按实体短名或实体 ID 过滤，只改变可见行，不改排序。
- **实体列表**：显示短名、类型、当前状态摘要、关联事件数；行内“时间线”直接打开该实体时间线。
- **动作持久化修复**：`normalizeRecord()` 之前只保留对象型 `action`，导致模式 A direct 记录（`action: '转移'`）落库后丢失动作；现在保留字符串动作，旧式结构化动作兼容。动作列使用中文字段标签并把实体 ID 转为短名。
- **版本**：0.5.0；事件/实体列表不再默认以原始 JSON 展示。

## 本阶段已完成（0.4.0–0.4.1）

- **主节点提及识别**：`lib/mention-resolver.js` 纯文本识别实体短名/别名；按文本位置排序、同位最长匹配；`lib/memory-retrieval.js` 支持显式 ID/短名或 `mentionText`。
- **关系线补充（§2.3）**：`collectRelationLine()` 从主节点的一跳候选实体中只返回当前状态摘要；按“直接同事件 → 同互动/同楼层 → 实时入度”排序；默认宽度 3，可配置。
- **主节点时间线**：`retrieveMainNodeTimeline()` 向过去追溯被提及实体的记录，受 `timelineDepth`（默认 20 条）限制；活跃区间不重复注入；不含未来楼层。
- **合并与去重（§2.4）**：`buildMemoryText()` 合并当前状态、回放、主节点时间线、同互动记录；记录按 ID 去重，状态卡按实体 ID 去重，事件按 `(楼层, 楼内序号)` 排序。
- **预算裁剪**：先砍关系线间接实体，再砍最早的非保护回放记录；主节点时间线与同事件分组记录受保护；受保护内容超预算时返回 `overBudget`，不静默丢失。
- **状态卡可读输出**：三类卡始终输出 §2.1 最小字段集；未知值显示 `未知`，不推断为事实。
- **运行时注入**：`memoryInjector` 生成文本时使用当前聊天最后一条用户消息作为提及文本、当前楼层作为时间上界；注入仍默认关闭、需手动应用（D-ILBM-011）。
- **新增 API**：`window.ILBM_MEMORY.previewCurrentTurn(options)`；`buildMemoryText()` 新增 `mentionText / relationLine / relationLineWidth / timelineDepth / activeWindowLayers / replayLayers` 选项。
- **设置项**：`relationLineWidth`（默认 3）、`timelineDepth`（默认 20）。可通过 `setSettings` 修改；面板“检索与注入”分区已提供输入框、当前轮注入预览和手动注入开关。
- **版本**：0.4.1；面板标记说明已改为严格 v2 语法，不再错误提示旧 `(((ILBM)))` 兼容。
