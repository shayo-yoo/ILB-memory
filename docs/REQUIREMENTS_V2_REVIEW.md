# v2 需求阅读记录

## 已确认的 v2 核心变化

1. 范围锁定为 SillyTavern + ILB 环境，不追求通用记忆架构。
2. 正则与标记识别委托 ILB-regex，ILBM 不再独立实现通用正则引擎。
3. 标记为内联结构化格式：`(((ILBM:[entity:甲] 转移 [entity:短剑] 给 [entity:乙])))`。
4. 记忆由当前状态、单向历史重放、关系线补充三部分组成。
5. 时间线只向过去追溯；关系线只做一跳横向关联，且不进入时间线追溯。
6. 当前状态必须由全部有效历史线性扫描推导，不使用指针推导状态。
7. 记录状态包括“待确认 / 有效”；待确认记录不参与状态计算和注入。
8. 提取模式为 `direct`（AI 直出）、`post`（事后提取）、`manual`（手动编辑）。
9. 第 N 层候选事件在第 N+1 层用户消息出现时确认有效；Swipe/重生成会使旧候选作废。
10. 注入前需合并去重、按楼层排序，并受记录数与 Token 预算约束。
11. 记忆数据应通过 `window.ILB.api.set` 随聊天变量保存，随 chat 备份和分叉继承。
12. UI 必须支持事件列表、实体列表、状态查看、提取结果检查、时间线/关系线设置、提取模式/API 设置和手动编辑。
13. 所有未验证的 ST、ILB、ILB-regex 能力必须标记为待验证，不得假设接口存在。

## v2 MVP 顺序

1. 接口与环境验证
2. 实体与事件存储
3. AI 事件提取（direct/post）
4. 当前状态计算
5. 记忆重放
6. 关系线补充
7. 编辑、分支与稳定性
8. 界面与优化

本记录只确认已阅读和理解，不代表以上未完成项已经实现。
