# ILBM 标记提示词与语法（模式 A）

> 适用版本：ILBM `0.7.x`。依据：`ILBMemory需求文档v2.md` §5.3、§6。
> 本文回答两个问题：AI 应该输出什么语法；ILBM 如何让 AI 知道这套语法。

## 1. 现状：ILBM 不会自动改写系统提示词

ILBM 当前负责：

- 过滤用户可见回复中的 `(((ILBM:...)))`；
- 从下一轮请求副本中清理标记；
- 捕获 assistant 消息并解析为事件记录；
- 模式 B 用自己的提取提示词调用外部 API。

ILBM **默认不会**把标记说明注入系统提示词。原因：

- 需求 §8 要求不擅自假设/修改 ST 或 ILB 的提示词结构；
- 用户可能已经通过 ILB 的提示词注入、角色卡、世界书或系统提示词管理输出格式；
- 自动注入会与用户的提示词方案冲突。

因此有两条使用路径：

1. **推荐：复制本文的提示词**，放入 ILB 的提示词注入、ST 系统提示词或世界书；
2. 在 ILBM 管理面板“标记处理”中点击“查看给 AI 的标记提示词”，再选择“开启提示词注入 → 立即注入提示词”，把它作为独立的 extension prompt（默认关闭，可随时清除）。

两种方式使用同一份文本（`lib/marker-prompt.js`），不会产生语法分歧。

## 2. 标记语法

外层固定为：

```text
(((ILBM:[entity:主体] 动作 [entity:客体] [entity:接收者] 补充说明)))
```

实际使用的简化形式：

```text
(((ILBM:[entity:甲] 转移 [entity:短剑] 给 [entity:乙])))
```

规则：

- 只有 `(((ILBM:...)))` **内部**的 `[entity:短名]` 会被识别；外部同名文本不碰。
- 一个标记只写一个动作；同一回复多个动作写多条标记。
- 实体顺序固定为 **主体、客体、接收者**（不是文本位置，而是标记中实体出现的顺序）。
- 不需要写前值/后值；程序按动作与当前状态推导。
- 空行、换行、解释文字不要放进标记内部。
- 标记对用户不可见，也会从下一轮请求副本中清除。
- 没有值得记录的变化时不要输出标记。

## 3. 状态动作白名单

只有下列动作会产生状态变更；其余叙事动作可以自由写，但不会改变状态。

| 动作 | 实体顺序 | 效果 |
|---|---|---|
| `转移` / `交给` | 主体、物品、接收者 | 物品持有者变为接收者 |
| `获得` | 主体、物品 | 物品持有者变为主体 |
| `失去` | 主体、物品 | 物品持有者清空 |
| `移动` | 主体、地点 | 主体位置变为地点（人物/物品均可） |
| `损坏` | 物品 | 物品状态=损坏 |
| `修复` | 物品 | 物品状态=完好 |
| `销毁` | 物品 | 物品状态=已销毁 |
| `遗失` | 物品 | 物品状态=遗失 |
| `死亡` | 角色 | 持续状态增加“死亡” |
| `受伤` | 角色 | 持续状态增加“受伤” |
| `中毒` | 角色 | 持续状态增加“中毒” |
| `建立关系` | 主动方、被动方、角色 | 建立有向关系 |
| `解除关系` | 主动方、被动方、[角色] | 解除关系；不写角色时解除该目标全部关系 |

示例：

```text
(((ILBM:[entity:铁匠] 转移 [entity:短剑] 给 [entity:甲])))
(((ILBM:[entity:甲] 使用 [entity:短剑] 与敌人交战)))
(((ILBM:[entity:甲] 转移 [entity:短剑] 给 [entity:乙])))
(((ILBM:[entity:短剑] 移动 [entity:营地])))
(((ILBM:[entity:短剑] 损坏)))
(((ILBM:[entity:甲] 受伤)))
```

`使用` 不在白名单，是自由叙事动作，不会改变状态；它仍然会作为事件记录保存，便于时间线回忆。

## 4. 关系：有向边与角色

关系格式：

```text
(((ILBM:[entity:主动方] 建立关系 [entity:被动方] 角色词)))
```

### 对称关系（写一条即可）

朋友、敌人、盟友、家人、恋人：

```text
(((ILBM:[entity:甲] 建立关系 [entity:乙] 朋友)))
```

程序会补出反向边；重复写入按 `(目标, 类型)` 去重。

### 不对称关系（必须写两条）

主仆、夫妻、亲子、俘虏、主宠：

```text
(((ILBM:[entity:甲] 建立关系 [entity:乙] 主人)))
(((ILBM:[entity:乙] 建立关系 [entity:甲] 仆人)))
```

```text
(((ILBM:[entity:甲] 建立关系 [entity:乙] 丈夫)))
(((ILBM:[entity:乙] 建立关系 [entity:甲] 妻子)))
```

角色词：`主人`、`仆人`、`丈夫`、`妻子`、`父母`、`子女`、`看守`、`俘虏`、`宠物`。
“主人”同时属于主仆/主宠；需要区分时写 `主仆:主人` 或 `主宠:主人`：

```text
(((ILBM:[entity:甲] 建立关系 [entity:乙] 主宠:主人)))
```

解除：

```text
(((ILBM:[entity:甲] 解除关系 [entity:乙])))          // 解除该目标全部关系
(((ILBM:[entity:甲] 解除关系 [entity:乙] 朋友)))      // 只解除朋友关系
```

状态卡显示为 `对乙：主人`；叙事注入显示为 `甲是乙的主人`。

## 5. 完整中文提示词（复制使用）

```text
【ILBM 记忆标记规则】
当剧情中发生需要长期记忆的事实变化时，在回复末尾追加内联标记；标记对用户不可见。
格式严格为：
(((ILBM:[entity:主体] 动作 [entity:客体] [entity:接收者] 补充说明)))
规则：
1. 只识别 (((ILBM:...))) 内部的 [entity:短名]；外部同名文本不会被识别。
2. 一条标记只写一个动作；同一楼层有多个动作时写多条标记。
3. 实体顺序固定为：主体、客体、接收者。短名第一次出现会自动注册。
4. 不需要写前值/后值，程序会根据动作和当前状态推导。
5. 没有值得记录的变化时不要输出标记；不要为了凑格式编造事件。
6. 不要在标记里解释、换行或嵌套其他标记。

状态动作白名单（只有这些动作会改变状态）：
- 转移：主体把物品交给接收者。例：(((ILBM:[entity:甲] 转移 [entity:短剑] 给 [entity:乙])))
- 交给：转移的同义词。
- 获得：主体获得物品。例：(((ILBM:[entity:甲] 获得 [entity:短剑])))
- 失去：主体失去物品。例：(((ILBM:[entity:甲] 失去 [entity:短剑])))
- 移动：主体移动到地点（物品也可以用）。例：(((ILBM:[entity:短剑] 移动 [entity:营地])))
- 损坏 / 修复 / 销毁 / 遗失：物品状态变化。例：(((ILBM:[entity:短剑] 损坏)))
- 死亡 / 受伤 / 中毒：角色持续状态。例：(((ILBM:[entity:甲] 受伤)))
- 建立关系：主动方与被动方建立有向关系，尾部写角色。
  对称关系（朋友/敌人/盟友/家人/恋人）写一条即可。
  不对称关系必须写两条，双方各一条（主人/仆人、丈夫/妻子、父母/子女、看守/俘虏、主人/宠物）。
- 解除关系：解除指定关系；不写角色时解除该目标上的全部关系。
其余叙事动作可以自由描述，但不会改变状态，通常不需要写标记。
```

英文版可通过 API `ILBM_MEMORY.markerPrompt({ language: 'en' })` 获取。

## 6. 模式 B（事后提取）

模式 B 不需要 AI 输出标记：

- AI 正常回复即可；
- ILBM 在回复后调用外部模型提取事件；
- 若回复里仍出现标记，会被过滤，但**不会**触发模式 A 解析；
- 同一消息只允许一种模式提取。

## 7. 常见错误

| 现象 | 原因 |
|---|---|
| 标记显示在聊天里 | 标记外层不是 `(((ILBM:...)))`，或写成了其它括号 |
| 整条标记被拒绝 | 缺少 `[entity:...]`，或动作不在白名单 |
| 状态没变化 | 动作是自由叙事动作（如“使用”），不产生状态变更 |
| 关系只有单向 | 不对称关系只写了一条；需要双方各写一条 |
| 同名实体分成了两个 | 短名不一致；第一次出现后应复用同一短名 |
| 记录下一轮才生效 | 模式 A 新记录先存为 `pending`，下一层用户消息确认后才参与状态与注入 |

## 8. 相关文件与 API

- 提示词文本：`lib/marker-prompt.js`
- 标记解析：`lib/direct-parser.js`、`lib/action-state.js`
- 关系：`lib/relation-model.js`
- 过滤/捕获：`lib/ilbm-bridge.js`
- API：`ILBM_MEMORY.markerPrompt({language?})`、`ILBM_MEMORY.markerPromptInfo()`、`ILBM_MEMORY.markerPromptInjection.{enable,apply,disable,clear}`
