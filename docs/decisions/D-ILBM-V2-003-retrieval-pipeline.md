# D-ILBM-V2-003 · 检索、关系线与合并裁剪语义

- 日期：2026-11-16
- 状态：Accepted（代码级）；真实 ST/模型验证待完成
- 依据：`ILBMemory需求文档v2.md` §2.1–§2.4、§5.5、§6.2

## 决策

1. **主节点来源**
   - 调用方显式传入 `mentionedEntityIds`，或传入 `mentionText` 由 `lib/mention-resolver.js` 纯文本识别。
   - 识别只决定注入范围，不修改存储；未提及实体不触发关系线。
   - 运行时默认取当前聊天最后一条用户消息作为 `mentionText`。

2. **关系线只做一跳**
   - 从主节点参与的有效记录出发，按 §5.5 的三条客观规则收集一跳候选：同记录（直接相关）、同 `interactionId`、同楼层。
   - 被触发实体只输出当前状态摘要，不进入时间线追溯，也不再扩散。
   - 宽度上限读取 `settings.relationLineWidth`，默认 3，可用参数覆盖。
   - 排序：直接相关次数优先，其次同互动/同楼层次数与实时入度，最后按名称稳定排序。

3. **主节点时间线**
   - 主节点参与的有效记录，受 `settings.timelineDepth` 限制，默认 20。
   - **解释：`timelineDepth` 按“最近 N 条记录”截断，而不是按楼层数。** 需求只写“追溯上限”，未规定单位；该解释需在真实对话实验中确认（GAP-011）。
   - 活跃区间 `[latest-activeWindow+1, latest]` 由 ST 原文提供，时间线、回放、关系线共用同一 `getActiveWindowBoundary()`。

4. **合并与去重**
   - 事件记录按记录 ID 去重，按 `(楼层, 楼内序号)` 排序。
   - 状态卡按实体 ID 去重；主节点状态卡在前，关系线实体状态卡在后。
   - 主节点时间线记录与同 `interactionId` 记录标记为受保护，不参与预算裁剪。

5. **裁剪顺序**
   - 先裁关系线间接实体状态卡（从优先级最低的开始）。
   - 再裁回放区间中最早、且未受保护的历史记录。
   - 主节点状态卡、主节点时间线、同事件分组记录不裁。
   - 预算极小时仍保留最靠近活跃窗口的一条历史；若受保护内容本身超预算，返回 `overBudget: true`，不静默丢弃。

6. **时间单向**
   - 当前状态计算接受 `currentFloor`，过滤该楼层之后的记录。
   - 回放、时间线、关系线均不返回未来楼层记录。
   - 待确认/无效记录不参与状态、回放、关系线和时间线。

## 影响

- 新增 `lib/memory-retrieval.js`；`lib/memory-injection.js` 重写合并/裁剪；`lib/memory-model.js` 增加时间边界与设置项。
- 数据结构未新增持久化字段；`settings` 新增 `relationLineWidth`、`timelineDepth`。
- 关系线不落库指针，按记录实时推导，避免重复保存可推导数据（§9.1）。指针的“入度”同样在查询时计算。

## 已知限制

- 未在真实 ST 聊天中验证提及识别、时间线深度与注入预算。
- 注入仍默认关闭并需手动应用（D-ILBM-011）；运行时只负责生成最新文本。
- 事件记录文本仍可能保留标记内的实体占位语法，注入时已去除 `[entity:名称]` 外壳，但不重写为完整自然语言句子。
- 关系线宽度设置尚未接入可视化界面。
